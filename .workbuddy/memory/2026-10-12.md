## 首页刷新控制台 504 报错排查
- **现象**：dev（`npm run dev`，localhost:4321）刷新控制台报 `GET .../dev-toolbar/entrypoint.js net::ERR_ABORTED 504 (Outdated Optimize Dep)`。
- **根因**：Phase 1 装新依赖（yaml/fast-xml-parser/jsonpath-plus）时 dev server 仍在运行，Vite 预构建缓存（optimizeDeps）陈旧，触发 "Outdated Optimize Dep" 504。
- **关键区分**：同屏另外 3 条报错（`color-material-extract` content script、chrome-extension manifest.json 加载被拒、`pino` 报错）**与 sw-tools 无关**，来自本机浏览器扩展注入到 localhost 页面，可忽略或测试时停用扩展对 localhost 的访问。

## 方向型工具「自动识别」再修复：方向被锁定导致换格式不识别（用户反馈"强制检测 JSON"）
- **现象**：用户在 JSON↔XML 等转换页，先贴 JSON 再贴 XML（或反之）时，第二项不自动转换，报错形如"不是合法 JSON"。
- **根因**：`converter-ui.ts` 的 `convertNow` 在 auto 模式下把 `detectDirection` 推断结果**写回下拉框**（`dirEl.value = effectiveDir`），使 `autoActive()`（判定 `dirEl.value==='auto'`）变 false；于是首次识别后下拉被锁定为旧方向，**后续输入不再重新识别**，直接沿用旧方向去 `JSON.parse`（XML/CSV 等非 JSON 输入）而报错 → 用户误以为"输入框强制 JSON 校验"。
- **修复**：引入 `userPickedDirection` 标志。`convertNow` 改为「只要 `dirEl.value==='auto'` 或用户尚未手动选过方向，就每次重新 `detectDirection` 推断」；仅当用户手动 `change` 下拉时才置 `userPickedDirection=true` 并停止自动识别（尊重手动选择）。删除已不再使用的 `autoActive()`。回显推断结果仍写回下拉框供用户可见。
- **验证**：写最小复现脚本（输入顺序 JSON→XML→JSON 数组）：旧逻辑第二项被锁定为 json2xml（XML 被当 JSON 解析报错），新逻辑正确跟随为 xml2json；`npm run build` exit 0，dist 10 个 HTML 均生成。临时脚本已删除。
- **影响面**：修复同时作用于 5 个方向型页面（yaml/xml/csv/base64/timestamp），均受益于"一次自动识别后仍能继续识别换格式"。
- **教训**：auto 模式若用"写回 UI 控件状态"作为内部模式判断依据，控件状态会被自己污染；内部模式应用独立布尔标志维护，UI 回显只做展示。

## formatter 压缩被失焦自动格式化覆盖（minify 不持久）
- **现象**：JSON 格式化页点「压缩」后内容正确压缩成单行，但点输入框外空白处，内容又被自动格式化（重新展开）。
- **根因**：`autoFormat()` 的 `blur` 监听里**无条件调用 `formatJson`** 把内容展开；`currentMode` 没有记忆，压缩只是一次性动作，下一次 `blur` 又无条件展开。点「压缩」按钮时其实先触发 `blur`（展开）→ 再触发 `click`（压缩），所以用户看到"压缩成功"，但模式没保持。
- **修复**：引入 `currentMode: 'format'|'minify'|'sort'`（默认 `'format'`）。新增 `transformByMode(text)` 按当前模式转换；`autoFormat()` 改用它，失焦自动应用"当前模式"；`format/minify/sort` 三个按钮在 `run()` 里设置 `currentMode`；缩进切换监听也改用 `transformByMode`（压缩模式缩进无意义，仍保持压缩）。仅 `format` 模式（真正的失焦自动美化）写入历史，避免压缩/排序重复写历史。页头与输入框占位符文案改为"自动应用当前格式"。
- **验证**：用正确入口 `node node_modules/astro/bin/astro.mjs build` 重建成功（dist 10 页全更新，formatter 含新文案）。
- **⚠️ 构建命令坑（重要）**：本仓库的 astro 可执行入口是 `node_modules/astro/bin/astro.mjs`，**不是** `node_modules/astro/dist/cli/index.js`（该文件只 `export { cli }`，直接 `node` 运行什么都不做、exit 0，会让人误以为构建成功）。沙箱里 `npm run build`/`ls`/`tail` 均因 PATH 异常不可用；正确做法是用托管 Node 绝对路径直接跑 `astro.mjs`，如：`/c/Users/sw/.workbuddy/binaries/node/versions/22.22.2-3/node.exe node_modules/astro/bin/astro.mjs build`。每次改完前端都要用此命令真构建并核对 dist 内容，不能只看 exit 0 或文件存在。

## 导航多列 + 新增图片处理分类
- **导航多列**：用户反馈分类下拉「全部一列、工具多了下拉过长」。改 `src/components/Header.astro`：桌面 mega-menu 分类面板在 `g.items.length > 4` 时改用 2 列网格（`grid grid-cols-2`）+ 加宽面板 `w-[40rem] max-w-[calc(100vw-2rem)]`，否则维持单列 `w-64`；搜索结果分组也改为 `sm:grid-cols-2`，缩短整体高度。逻辑仍数据驱动 `toolsByCategory()`，新增分类/工具自动生效。
- **新增图片处理分类**：`src/lib/tools.ts` 加 `image` 到 Category 联合类型 + `CATEGORY_META['image']`（名称「图片处理」、图标 `image`），并注册 3 个 ready 工具：`image-convert`(图片格式转换,/image/convert)、`image-compress`(图片压缩,/image/compress)、`image-edit`(裁剪/翻转/旋转,/image/edit)。
- **共享库** `src/lib/image/process.ts`：纯前端 Canvas 实现 `loadImage / imageToCanvas / canvasToBlob / flipCanvas / rotateCanvas / cropCanvas / resizeCanvas / flattenAlpha / download / formatBytes / extForType / outName`，全部本地处理不上传。浏览器可编码导出仅 PNG/JPEG/WebP（GIF 无法编码，输入 GIF 仅取首帧并在 UI 注明）。
- **3 个页面**（Base 布局 + 面包屑 + 拖拽上传 dropzone + 预览 + 信息/下载）：
  - convert：目标格式 select(PNG/JPEG/WebP) + 质量滑块(仅 JPEG/WebP 启用) + JPEG 透明填充白色；实时预览 + 原图/输出体积与变化百分比。
  - compress：质量滑块(仅 JPEG/WebP 启用，PNG 无损则隐藏) + 可选最大宽度；输出保持原格式(不可编码者转 PNG) + 压缩比例。
  - edit：可拖拽移动的选框 + 右下角手柄缩放 + X/Y/宽/高数值微调；水平/垂直翻转、旋转 90/180/270、应用裁剪、整图选框、重置；预览 Canvas 按显示比例定位选框（`dispScale = clientWidth/width`，随窗口 resize 更新）；下载为 PNG。
- **图标**：`src/components/Icon.astro` 新增 `image`/`crop`/`flip`/`compress` 四个 path。
